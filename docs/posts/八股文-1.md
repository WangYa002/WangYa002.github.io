# HTTP与TCP：面试必备知识点

## TCP三次握手

```text
客户端 -> SYN -> 服务端
客户端 <- SYN+ACK <- 服务端
客户端 -> ACK -> 服务端
```

### 为什么需要三次？

- 第一次：服务端确认客户端发送能力正常
- 第二次：客户端确认服务端接收和发送能力正常
- 第三次：服务端确认客户端接收能力正常

## TCP四次挥手

```text
客户端 -> FIN -> 服务端
客户端 <- ACK <- 服务端
客户端 <- FIN <- 服务端
客户端 -> ACK -> 服务端
```

### 为什么需要四次？

- 第一次：客户端请求断开，表示不再发送数据
- 第二次：服务端确认，但可能还有数据要发送
- 第三次：服务端完成发送，请求断开
- 第四次：客户端确认，双方完全断开

## HTTP常用状态码

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | 协商缓存 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |

## HTTP keep-alive

HTTP/1.1 默认开启 keep-alive，一个TCP连接可以处理多个HTTP请求，避免频繁建连的性能损耗。
