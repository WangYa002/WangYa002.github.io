## 第 1 题：结构体内存对齐（sizeof = 8）

```c
struct st {
    char a;
    short b;
    int c;
};
```

**问：`sizeof(st) = ?`**

**答：8。** 考点是 C 语言结构体内存对齐，两个要点：

1. 每个成员的起始地址必须是该类型大小的整数倍；
2. 结构体整体的大小必须是其中最大成员大小的整数倍。

> 根据上面两个要点：a 占 1 个字节，但 short 要求 2 字节对齐，所以 a 后面填充 1 个字节；b 占 2 个字节；c 占 4 个字节，一共 8 个字节。整体大小 8 又是最大成员 int（4 字节）的整数倍，所以为 8。

## 第 2 题：结构体内存对齐（sizeof = 12）

```c
struct st {
    char a;
    int b;
    short c;
};
```

**问：`sizeof(st) = ?`**

**答：12。**

> char 占 1 个字节，int 要求 4 字节对齐所以填充 3 个字节，然后 int 占 4 个字节，short 占 2 个字节，此时结构体大小为 10。但整体大小必须是最大成员 int（4 字节）的整数倍，所以再填充 2 个字节，最终达到 12。

## 第 3 题：有符号与无符号的隐式转换

```c
#include <stdio.h>
void foo() {
    unsigned int a = 6;
    int b = -20;
    (a + b) > 6 ? puts(" > 6") : puts(" < 6");
}
```

**问：最终输出是？**

**答：` > 6`**

> 在执行 `a + b` 时发生了隐式类型转换：a 和 b 的整型转换级别相同，编译器会将有符号整型 b 隐式转换为无符号整型。
>
> 补码运算：在常见的 32 位系统下，-20 的补码表示为 0xFFFFFFEC，即无符号值 4294967276，执行加法 6 + 4294967276 = 4294967282。
>
> 关系比较 `a + b > 6` 时，右侧的 6 同样提升为 unsigned int 进行比较，此时 4294967282 > 6 成立。

## 第 4 题：strcpy 缓冲区溢出

```c
int main() {
    char a;
    char *b = &a;
    strcpy(b, "Hello");
    printf("%s", b);
    return 0;
}
```

**问：上面哪里会执行出错？**

**答：会在执行 `strcpy(b, "Hello")` 处引发严重的缓冲区溢出（Buffer Overflow）**，通常会导致程序崩溃、段错误（Segmentation Fault）/ Stack Smashing。

> 首先变量 a 只是一个普通的字符变量 char，在内存中仅占用 1 字节的空间；指针 b 指向 a 的内存地址，即只有 1 字节的合法存储空间。字符串 `"Hello"` 包含 5 个字符加上末尾的空字符 `\0`，总共需要 6 个字节。
>
> strcpy 会将 6 个字节完整写入以 b 开头的内存区域，向后破坏栈帧上的其他数据。在 MSVC 编译器上测试，能够打印 Hello，但栈已被破坏。

## 第 5 题：字符串字面量的只读性

```c
int main() {
    char* s = "AAA";
    s[0] = 'B';
    printf("%s", s);
    return 0;
}
```

**问：哪里会出错？**

**答：`char* s = "AAA";` 这一行就会报错，类型不匹配。**

> C++11 之后，字符串字面量 `"AAA"` 是严格的 `const char[4]`，C++ 禁止将 `const char*` 隐式转换为普通指针 `char*`，以防止通过非 const 指针意外修改只读内存，因此编译器在 `char* s = "AAA"` 处直接报错。
>
> 即使在 C 语言中这行只给出警告（gcc 默认行为），下一行 `s[0] = 'B'` 对只读段（.rodata）的写入依然会触发段错误。MSVC 下实测：`char* s = "AAA"` 报 C2440 类型转换错误。

## 第 6 题：大小端序存储的区别

**答：** 大小端序是指多字节数据在计算机内存中按字节排列的先后顺序。单个字节本身并不存在大小端问题，只有占用 2 个及以上字节数的数据类型才涉及字节序。

> **小端序**：低位字节存储在低内存地址端，高位字节存储在高内存地址端。常见架构：x86、x64、大多数 ARM 处理器。
>
> **大端序**：高位字节存储在低内存地址端，低位字节存储在高内存地址端。常见场景：网络传输协议（TCP/IP 规定网络字节序为大端序）、部分 RISC 架构。

内存对比示例：以 32 位十六进制整数 `0x12345678` 为例（共占用 4 字节）：

- **最高有效字节（MSB）**：`0x12`
- **最低有效字节（LSB）**：`0x78`

假设起始内存地址为 `0x1000`：

| **内存地址**       | **小端序存储的内容** | **大端序存储的内容** |
| ------------------ | -------------------- | -------------------- |
| `0x1000`（低地址） | `0x78`（低位）       | `0x12`（高位）       |
| `0x1001`           | `0x56`               | `0x34`               |
| `0x1002`           | `0x34`               | `0x56`               |
| `0x1003`（高地址） | `0x12`（高位）       | `0x78`（低位）       |

## 第 7 题：C++ 产生临时对象的几种场景

**1. 函数以值传递方式传参（Pass by Value）**

当向函数传递参数且形参类型为值类型时，会调用拷贝构造函数或移动构造函数生成形参对象；实参在进入函数时若涉及隐式转换，也会生成临时对象。

```cpp
void foo(MyClass obj);
foo(MyClass()); // 实参本身是临时对象
```

**2. 函数以值传递方式返回（Return by Value）**

函数返回非引用类型的对象时，会构造一个临时对象作为返回值传递给调用方（现代 C++ 编译器在满足特定条件时，会通过 RVO/NRVO 返回值优化直接省略该临时对象的生成）。

```cpp
MyClass createObject() {
    MyClass a;
    return a; // 在未触发或不支持优化的场景下，会生成临时对象返回
}
```

**3. 表达式计算与运算符重载的中间结果**

算术运算、拼接运算或运算符重载（operator+）通常以值的形式返回计算结果，该中间结果是一个临时对象。

```cpp
string s1 = "hello";
string s2 = "world";
string s3 = s1 + s2; // s1 + s2 运算会生成一个 std::string 的临时对象
```

**4. 隐式类型转换（Implicit Conversion）**

当传递或赋值的实参类型与目标类型不一致，但存在可调用的单参数构造函数（且未声明为 explicit）或类型转换运算符时，编译器会自动构造一个临时对象来完成适配。

```cpp
void printString(const std::string& str);
printString("hello"); // 字符串字面量 "hello" 是 const char*，编译器会隐式调用 string 构造函数生成一个临时 string 对象
```

**5. 常量左值引用或右值引用绑定不同类型/右值时**

绑定到不同类型，发生转换：

```cpp
int a = 10;
const double& ref = a; // 编译器先生成一个 double 类型的临时对象存放 10.0，然后 ref 绑定到该临时对象上（延长其生命周期）
```

右值引用直接绑定字面量或表达式：

```cpp
MyClass&& r = MyClass(); // 临时对象生命周期被延长
```

**6. 显式类型转换（强制类型转换/函数式类型转换）**

通过类型构造表达式显式强转时，直接在求值位置生成临时对象。

```cpp
MyClass obj = (MyClass)10; // C 风格强转
MyClass obj2 = MyClass(20); // 显式直接构造对象
```

**7. 异常处理中抛出异常对象（throw 表达式）**

当执行 throw 语句抛出局部对象时，由于局部对象随着函数栈展开会被销毁，C++ 运行时会在专门的异常内存区域构造一个临时异常对象，传递给 catch 子句。

```cpp
void test() {
    MyException e;
    throw e; // 会拷贝/移动构造一个临时的异常对象传递给 catch 块
}
```

### 延伸：RVO、NRVO 与移动语义，避免临时对象的开销

#### 一、RVO 与 NRVO：从根源消除临时对象

RVO（Return Value Optimization，返回值优化）和 NRVO（具名返回值优化）属于编译器优化技术（Copy Elision，复制省略）。

**1. 传统无优化流程的问题**

假设没有返回值优化，以下代码会经历多轮昂贵的拷贝或构造：

```cpp
MyClass create() {
    return MyClass(); // 步骤 1：构造纯右值临时对象
}
MyClass obj = create();
```

- 步骤一：在 create() 函数内部构造一个局部/临时对象；
- 步骤二：在调用方的栈帧中构造一个临时对象，将函数内部的对象拷贝过去；
- 步骤三：调用方将临时对象拷贝构造给 obj；
- 步骤四：析构函数内部对象与临时对象，这个过程伴随着多次深拷贝与内存分配。

总结：相当于为了给 obj 赋值，产生了两个临时对象。

**2. RVO（无名返回值优化）**

当函数返回的是一个未具名的临时纯右值时：

```cpp
MyClass create() {
    return MyClass(); // 纯右值
}
MyClass obj = create();
```

优化机制：编译器在调用 create() 时，会向函数隐式传递一个隐藏参数（即外层 obj 的内存地址）。create() 函数不再创建任何中间临时对象，而是直接在调用方的 obj 所在内存空间上进行原地构造。

开销：原本的"构造 + 拷贝/移动 + 析构"被优化为仅有一次构造。

C++17 强制复制省略：从 C++17 开始，RVO 升级为语言规则，即使该类的拷贝构造函数被 `= delete` 禁用，代码依然合法且不会触发拷贝。

**3. NRVO（具名返回值优化）**

当函数返回的是一个有名字的局部变量（左值）时：

```cpp
MyClass create() {
    MyClass localObj;
    return localObj; // 具名局部变量
}
MyClass obj = create();
```

- 优化机制：与 RVO 类似，编译器尝试直接让局部变量 localObj 的地址映射到外部接收者 obj 的栈内存中。
- 限制：NRVO 依赖编译器的静态分析。如果函数存在多个可能返回不同局部对象的控制分支，编译器可能无法提前确定到底使用哪个局部对象，此时 NRVO 可能会失效。

#### 二、移动语义（Move Semantics）：优化不可省略时的兜底方案

**1. 所有权转移而非深拷贝**

深拷贝需要重新申请堆内存并复制字节内容；而移动构造函数利用右值引用，直接窃取源对象持有的堆指针或系统资源句柄，并将源对象内部指针置为空指针（nullptr）。

```cpp
class MyString {
    char* data;
    size_t len;
public:
    // 拷贝构造函数：深拷贝，开销大（O(N)）
    MyString(const MyString& other) {
        data = new char[other.len + 1];
        strcpy(data, other.data);
        len = other.len;
    }

    // 移动构造函数：浅拷贝资源，开销极低（O(1)）
    MyString(MyString&& other) noexcept {
        data = other.data; // 窃取指针
        len = other.len;
        other.data = nullptr; // 置空，防止源对象析构时重复释放内存
        other.len = 0;
    }
};
```

**2. 在返回值中的应用**

如果函数返回局部变量，且 NRVO 没有成功触发：

- C++ 标准规定：在 `return localObj;` 语句中，编译器会自动将具名局部变量视为右值；
- 此时若类定义了移动构造函数，系统会优先调用移动构造函数将资源转移给接收者，而不是去调用高开销的深拷贝构造函数。

#### 三、常见反模式：对返回值使用 std::move

```cpp
MyClass create() {
    MyClass localObj;
    return std::move(localObj);
}
```

为什么是反模式：

1. `std::move(localObj)` 的类型是 `MyClass&&` 右值引用，而函数返回值类型是 MyClass 值，这会直接破坏 NRVO 的触发条件；
2. 编译器原本有机会做 NRVO 实现零拷贝原地构造；一旦加上 std::move，强制将优化降级为移动构造，适得其反；
3. 即使 NRVO 失效，编译器在 return 局部变量时也会自动将其视为右值去匹配移动构造，显式写 std::move 毫无必要。

## 第 8 题：常用数据结构

**vector：**

> - 底层实现：一段连续的线性内存空间（通过三个指针维护：start 指向首元素、finish 指向有效元素末尾、end_of_storage 指向容量末尾）
> - 核心特点：支持 O(1) 随机访问；尾部插入/删除为均摊 O(1)；中间或头部插入/删除需移动后续元素，时间复杂度为 O(N)
> - 扩容机制：当容量不足（size == capacity）时，重新申请一块更大的连续空间（GCC 为 2 倍，MSVC 为 1.5 倍），将原元素拷贝/移动到新空间并释放旧内存，此时原有迭代器与指针全部失效

**stack：**

> - 底层实现：容器适配器，默认基于 deque 封装实现，也可以显式指定 vector 或 list 作为底层容器
> - 核心特点：遵循 FILO 先进后出原则，只允许在栈顶进行压入 push、弹出 pop 和访问 top，操作复杂度均为 O(1)；封锁了底层容器的随机访问接口，不提供迭代器，无法遍历

**priority_queue：**

> - 底层实现：容器适配器，默认以 vector 为底层容器，配合堆算法实现的完全二叉树，默认是大顶堆 std::less\<T\>
> - 核心特点：队首（堆顶）始终是优先级最高的元素。获取堆顶 top() 为 O(1)，插入 push() 与弹出 pop() 涉及堆的上浮与下沉调整，时间复杂度均为 O(log N)

**queue：**

> - 底层实现：容器适配器，默认基于 deque 实现，也可以指定 list，但是不能用 vector，因为 vector 缺乏高效的头部删除 pop_front 接口
> - 核心特点：遵循 FIFO 先进先出原则，队尾入队，队头出队，操作复杂度均为 O(1)，同样不支持迭代器与随机访问

**deque：**

> - 底层实现：分段连续内存。由一个中央控制器（map 指针数组）管理多个固定大小的连续缓冲区 buffer，逻辑上表现为连续空间
> - 核心特点：头尾两端的插入与删除均为 O(1)；支持 O(1) 随机访问，但寻址需经过两次指针解引用，略低于 vector，适合高频在头尾增删元素的场景

**map：**

> - 底层实现：红黑树，一种自平衡二叉搜索树，每个节点存储键值对 std::pair\<const Key, Value\>
> - 核心特点：元素按 Key 自动升序排列，Key 唯一不可重复；查找、插入、删除操作的时间复杂度稳定在 O(log N)；迭代器增减遍历即为有序序列

**unordered_map：**

> - 底层实现：哈希表，采用"桶数组 + 链表"的拉链法解决哈希冲突
> - 核心特点：元素无序存储，Key 唯一；平均查找、插入、删除时间复杂度为 O(1)，最坏情况（发生极端哈希碰撞退化为单链表）为 O(N)；负载因子超阈值时会触发 rehash 扩容

| **数据结构**          | **底层结构**                     | **随机访问** | **增删效率**                  | **元素有序性** |
| --------------------- | -------------------------------- | ------------ | ----------------------------- | -------------- |
| **`vector`**          | 连续内存数组                     | O(1)         | 尾部 O(1)，其余 O(N)          | 按插入顺序     |
| **`deque`**           | 中控器 + 分段连续缓冲区          | O(1)         | 头尾 O(1)，中间 O(N)          | 按插入顺序     |
| **`stack` / `queue`** | 适配器（默认 `deque`）           | 不支持       | 端口操作 O(1)                 | FILO / FIFO    |
| **`priority_queue`**  | 适配器（默认 `vector` + 二叉堆） | 不支持       | 堆顶 O(1)，增删 O(log N)      | 堆顶极值       |
| **`map`**             | 红黑树                           | 不支持       | O(log N)                      | 按 Key 有序    |
| **`unordered_map`**   | 哈希表（拉链法）                 | 不支持       | 平均 O(1)，最坏 O(N)          | 无序           |

## 第 9 题：IPC 进程间通信方式

**管道：**

> - 原理：在内核内存中开辟一块固定大小的缓冲区（环形队列），通过 pipe() 系统调用返回两个文件描述符，一个读端 fd[0]，一个写端 fd[1]
> - 特点：半双工通信（数据单向流动，若需要双向通信需创建两个管道）；没有名字，仅限于具有亲缘关系的进程之间使用；传递的是无格式字节流，生命周期随进程结束而销毁

**命名管道：**

> - 原理：一种特殊的文件类型，通过 mkfifo 创建，在文件系统中拥有可见的路径名，提供访问入口，但数据依然在内核缓冲区传输，不落盘
> - 特点：遵循先进先出原则，突破了亲缘关系限制，允许本机任意两个不相关的进程通过打开同一个 FIFO 文件路径进行通信

**信号：**

> - 原理：在软件层次上对硬件中断机制的模拟，是一种异步通信机制。内核或进程通过 kill/raise 向目标进程发送信号（SIGINT、SIGKILL、SIGSEGV）
> - 特点：是唯一的异步 IPC 方式，用于通知进程某事件发生；携带信息量极小，仅包含信号编号，目标进程可通过捕捉、忽略、执行默认动作来响应

**信号量：**

> - 原理：本质是内核维护的一个原子计数器，配合两个原子操作：P 操作（wait，计数器减 1，若小于 0 则阻塞）和 V 操作（signal，计数器加 1，唤醒阻塞进程）
> - 特点：不以传输业务数据为目的，而是专门用于解决多进程/多线程对临界资源访问的同步与互斥问题，常作为共享内存的配套同步锁使用

**消息队列：**

> - 原理：保存在内核中的消息链表，每个消息是一个带有特定类型标识和数据长度的块
> - 特点：克服了管道无格式字节流和信号承载信息量少的缺点；支持按消息类型随机读取，解耦了发送方与接收方；缺点是消息大小受内核限制，且读写过程中存在用户态与内核态之间的数据拷贝开销

**共享内存：**

> - 原理：多个进程将同一块物理内存区域映射到各自独立的虚拟地址空间中，进程直接像访问普通内存指针一样读写数据
> - 特点：所有 IPC 中速度最快的方式，因此彻底省去了数据在用户态与内核态之间来回拷贝的开销；缺点是本身不具备任何同步与互斥机制，多进程并发读写时必须配合信号量/互斥锁使用

**套接字：**

> - 原理：提供端到端的通信抽象接口，既可以基于网络协议栈（TCP/UDP）传输，也可以基于本地内核（Unix Domain Socket）传输
> - 特点：最通用的通信方式，不仅支持本机无亲缘关系的进程间通信，更是唯一原生支持跨网络、不同主机间进程通信的机制

| **IPC 方式**           | **亲缘关系要求**    | **数据格式/性质**         | **通信效率**           | **核心用途**                         |
| ---------------------- | ------------------- | ------------------------- | ---------------------- | ------------------------------------ |
| **匿名管道 (Pipe)**    | 必须有（父子/兄弟） | 无格式字节流              | 一般（需内核拷贝）     | 具有亲缘关系的简单流传输（如 Shell 管道） |
| **命名管道 (FIFO)**    | 无要求              | 无格式字节流              | 一般（需内核拷贝）     | 本机任意进程间的单向字节流传输       |
| **信号 (Signal)**      | 无要求              | 信号编号（异步通知）      | 极快                   | 异常通知、进程控制与事件唤醒         |
| **信号量 (Semaphore)** | 无要求              | 原子计数器                | 极快                   | 进程/线程间的互斥与同步控制          |
| **消息队列**           | 无要求              | 有格式/类型的消息块       | 一般（需内核拷贝）     | 本机进程间按类型解耦收发结构化数据   |
| **共享内存**           | 无要求              | 原始内存字节              | **最快**（零内核拷贝） | 本机进程间高频、大数据量交互         |
| **套接字 (Socket)**    | 无要求              | 字节流(TCP) / 数据报(UDP) | 较慢（涉及协议栈开销） | 跨主机网络通信或本机通用通信         |

## 第 10 题：编程题 —— 删除字符串中相邻的重复字符

> 输入：`"abbaca"`
>
> 输出：`"ca"`

**解法一：栈模拟**

```cpp
string removeSame(string& s) { // 栈模拟
    string res = "";
    for (char c : s) {
        if (res == "" || res.back() != c) {
            res.push_back(c);
        } else {
            res.pop_back();
        }
    }
    return res;
}
```

**解法二：双指针模拟**

```cpp
// 双指针模拟
string removeSame(string& s) {
    int top = 0; // 代表当前有效栈的长度
    for (int i = 0; i < s.size(); ++i) {
        if (top != 0 && s[top - 1] == s[i]) {
            top--;
        } else {
            s[top] = s[i]; // 压入栈
            top++;
        }
    }
    s.resize(top);
    return s;
}
```
